核心事实 (决定一切静态分析结论):
  F1. 检测/判定逻辑全部位于 VMP 虚拟化段 (0x5C72000-0x5CD847C)。
      静态字节 ≠ 运行时字节 —— VM 代码块执行时才解密 (auth3_branch_analysis.txt
      已实证: dump 中 0x5CA1CA1 是 5 字节, 运行时是 6 字节调用)。
      → 【任何静态 NOP/patch 都无效】。
  F2. 全 dump 无任何明文反分析字符串。frida/调试器/VM/分析工具名 0 命中。
      API 解析用 FNV-1a 哈希 (零 API 名明文), 字符串比较用哈希/即时解密。
  F3. 系统调用混合策略:

        = NtAllocateVirtualMemory) 和 0x878CDB (SSN 30 = NtFreeVirtualMemory)。

        Section 系/注册表系) 由 VMP 内即时解密的 stub 发起, 静态不可见。
      - 常规查询 (QIP cls=37/0/12/24/26/27/52) 运行时走 ntdll 导出 (可 hook 观测)。
  F4. 62 个用户态→VMP 段入口 (call rel32), 调用者聚集于 7 个功能区:

【3. 进程/模块扫描】
--------------------------------------------------------------------------------
  [P1] sub_14042AEE0 (RVA 0x42AEE0) —— API 哈希解析 + 内核模块定位 ★核心
    实现: PEB→Ldr→InLoadOrderModuleList 遍历 (gs:[0x60] @ RVA 0x42AF49/0x42B0A5),
    对每个 DLL 的导出表函数名算 32 位 FNV-1a (种子 921109335 与 -652722220),
    命中哈希 -752552233 / 1265834417 后取得函数地址缓存于 qword_142BF8DE0/DD8。
    用途: 解析 NtQuerySystemInformation(SystemModuleInformation, buf, 0x2000, &len)
    枚举内核模块 → GetModuleFileName 类调用取得路径 → 与【运行时解密出的
    "ntoskrnl.exe"】比较 → 缓存 ntoskrnl 基址 (qword_142BF8380)。
    "ntoskrnl.exe" 解密公式 (逐字节):
      aNtoskrnlExe[n] = (53*((-79*n)^0xDD^(((-1640531535*n)^0xB137E1DD)>>13)))
                      ^ ((-1028477387*((-1640531535*n)^0xB137E1DD^((... )>>13))>>16)
                      ^ byte_140A024F8[n]
    → 这是【内核交互原语】(找 ntoskrnl 供 RTCore64 IOCTL 用), 非反调试;
      但证明"零明文 API 名 + 哈希解析"是全程序风格。
    绕过: hook 对应 syscall (SSN 54 NtQuerySystemInformation) 过滤内核模块表。

  [P2] 进程枚举 (运行时实测):
    NtOpenProcess(pid=游戏 2132, 0x1000=VM_READ) —— 打开游戏读内存 (主业);
    NtOpenProcess(pid=自身, 0x410) —— 自扫描;
    QIP cls=27 查询外部句柄 h=1560/1520 的进程镜像名 —— 进程识别。
    CreateToolhelp32Snapshot/Module32First/Module32Next 明文串 (RVA 0xC32590)
    属于 OpenSSL dso_win32.c 动态库加载器, 【非】检测。

  [P3] 自带 DLL 加载器 (免疫注入检测 + 绕过 hook):
    运行时对 SspiCli/dwmapi/PrxerDrv/mswsock/CRYPTSP/rsaenh/CrashRpt/d2d1/
    DWrite/input/ktmw32/OLEACC/dbghelp/VERSION/USERENV 全部走:
      NtOpenSection(\\KnownDlls\\x.dll) → STATUS_OBJECT_NAME_NOT_FOUND
      → NtCreateSection(SEC_IMAGE) → NtMapViewOfSection 自行映射。
    效果: ① 不经 LoadLibrary, 用户态 hook 不可见; ② Ldr 模块表不记录,
    Frida Process.enumerateModules() 看不到; ③ 天然免疫 SetWindowsHookEx 注入。

【4. 内存完整性检测】
--------------------------------------------------------------------------------
  [M1] VMP 自加密 (最强的一道): 见 F1。段内代码执行时解密, 静态 patch 无效。
       auth3_branch_analysis.txt 已实证字节流差异。

  [M2] RWX shellcode 即用即焚模式 (FUN_1405F0AB0, RVA 0x5F0AB0) ★已完整逆向:
    流程:
      1) 70 (0x46) 字节加密 blob 以 18 个 dword 常量内联在栈上
         (0xA4BEE596, 0x63312F93, 0x6287D26D, 0xA3A84ABF, 0x8E87B4A4,
          0xFEB560CA, 0x6327E3E0, 0xFE1BFFE3, 0x4C4583A9, 0xEB0C35DC,
          0xCD9F33CB, 0x7893EC45, 0x3589DE267? =0x359DE267, 0xBC86467F,
          0xA1BD566D, 0x2107271D, 0x5F4DE96A, 0xD09B)
      2) 密钥: 栈构造 UTF-16 串 "0$D>!a!c!|n>a||a|m|0|0|x|a" (8 个 imm64:
         0x003000240044003E, 0x0021002100610021? …见 local_128..uStack_100)
         经 XOR-移位键流扩展
      3) FNV 变异流解密: `x = (x<<21)^x; x ^= x>>35; x = x^(x<<4); plain = enc^n`
      4) NtAllocateVirtualMemory(自身, RWX=0x40, 0x100)  ← 裸 stub 0x878CD0
      5) 拷入 → (*shellcode)(&out, 1) 执行 → 结果 8 字节
      6) 立即清零 shellcode 页 → NtFreeVirtualMemory(MEM_RELEASE) ← 0x878CDB
      7) 【执行两次】(同 blob 同密钥), 采集 CPU/硬件特征
    用途: 让 CPUID 类指令在匿名 RWX 页执行, 完全避开对主模块的指令级 hook。
    取证影响: dump 时机不巧就抓不到这 70 字节; 想抓需 hook 0x878CD0。

  [M3] 主代码段 CRC/校验循环: 段外不可见 (VMP 内的 integrity check 静态不可证)。
       实测影响: 对主模块 inline hook (Frida Interceptor) 未导致进程被杀
       (kr_v3.log 43s 存活) —— 校验即使存在也只上报不自杀。
