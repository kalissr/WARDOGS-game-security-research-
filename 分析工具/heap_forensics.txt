一、执行摘要（最重要结论）
--------------------------------------------------------------------------------
1. Agent L 报告的 0x595f10 / 0x596130 / 0x596680 是【主模块进程虚拟地址(VA)】，
   不是堆转储文件偏移。cap_heap.bin 在这三个偏移处【全部为 0x00】
   (0x595f00-0x596800 整个 0x900 字节区域 0 个非零字节)。
   → 堆转储只包含堆段，主模块 .data/.bss 段根本不在文件里。
   → 同理 Agent S 在 0x6d6520 看到的 "W" 常量表 (a573c29f...) 也是 VA，
     cap_heap.bin 偏移 0x6d6520 处同样全零。两位 Agent 的地址都是调试器 VA。

2. 堆中存在 VA 0x595f10 的唯一指针（文件偏移 0xcfa80），以及 6 个相邻
   解密缓冲 VA（0x596020/0x596130/0x596240/0x596350/0x596460/0x596570/
   0x596680，间隔 0x110）各自的唯一指针。这证明：7 个 0x110 间隔的静态
   缓冲（含 Agent L 的三个地址）是被堆中管理结构引用的模块级缓冲区数组。

3. 堆中存在该密码体系的【运行时副本】，真实位置：
   - 模板缓冲 3 份: 0xcef90 / 0xcf1b0 / 0xcf700 (240B = 32B标记码 + 208B常量)
     三份逐字节一致（差异 = 0）。这是 XOR 掩码/模板，不是会话密文。
   - 数据块 3 种: 0xcf0a0 (41f382bd..) / 0xcf3d0 (f39e1d9e..) / 0xcf4e0 (bdba0347..)
     其中 0xcf4e0 与 0xcf5e0 两份完全相同 —— 这才是"3 份副本"传说的真实来源。
   - 堆块序号链: seq 0x0f..0x1c 连续分配，模板与数据交替出现。

4. 判定状态变量：堆中找到多个 0/1/0x0f 标志候选（见第五节），
   但必须注意：真正的全局判定变量位于主模块 .data（VA 0x59xxxx 段），
   不在本堆转储内。堆内只能看到它的引用与关联对象。

5. 目标程序身份确认：RTTI 类型名 140 处命中 "<PRODUCT>" 命名空间
   (<PRODUCT>::Features::AimingAtYou / AirThreats / MissileWarning / EmuCall /
   menukit::gos::EspPreviewV4 等)。服务器 <AUTH_API> (<PROXY_SRV>:5695)。

----------------------------------------------------------------------------------------------------
整个 0x900 字节区域 = 全零（0 个非零字节）。无任何结构边界可标注。
