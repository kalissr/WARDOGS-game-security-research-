一、架构概述
============================================================
自动驾驶系统分为两大模块：
  1. 地面载具自动驾驶（含补给投送）
  2. 直升机自动驾驶

整体架构为"外部型"作弊——不注入游戏进程，通过 syscall 读取
游戏内存（UE 反射系统），在独立进程中计算路径和控制指令，
再通过跨进程写入 Discord 渲染层显示导航信息。

二、地面载具自动驾驶
============================================================
核心函数: 0x1405dd150 - 0x1405e0001 (12KB)
子模块:
  - 0x1405b5df0: 绕行障碍物
  - 0x1405b50f0: 燃料不足时加油
  - 0x1405b51c0: 低于此值必加油
  - 0x1405b5290: 返程途中进入车库区即停车购买
  - 0x1405b6470: 自动驾驶HUD

功能字符串（从功能映射表提取）:
  "卡住 - 已停止"
  "卡住 - 正在倒车"
  "此处无法加油"
  "未找到路线"
  "地面载具自动驾驶与补给投送"
  "障碍物 %.1f 米高"
  "未驾驶载具"

四、路径规划
============================================================
数据源: glTF 2.0 网格（从加密 cache 解密获得）
  - 43,988 个 3D 坐标点（X,Y 非零）
  - 四张地图: Europe / Kavkazi / NorthAmerica / Russia
  - 网格顶点用于构建可通行区域

路径算法: A* 状态机（从 Ghidra补编_功能区300函数.c 提取）
  - 以 glTF 网格为节点
  - 支持动态路径重算（"dynamic_path"）
  - 障碍物检测（"障碍物 %.1f 米高"）
  - 卡住检测（"卡住 - 已停止" → 倒车 → 重规划）

五、游戏内存读取（漏洞点）
============================================================
读取方式: NtReadVirtualMemory 直接系统调用
  - 使用 14 个直接 syscall（绕过 ntdll hook）
  - SSN 映射见 ssn_map.json

UE 反射系统访问:
  - Attribute.Gameplay.Health（血量）
  - UE偏移表: 4,279 个偏移（见 UE偏移表_修正版.json）
  - GObjects = 0x0D2C62B0
  - GNames 候选 = 0x0A784828
  - GWorld 候选 = 0x0A45F5C0

六、渲染（Discord 注入）
============================================================
渲染方式: 跨进程写入 Discord 客户端
  - 31 处跨进程写入点（见 注入模块_反编译_138函数.c）
  - Discord 渲染模块运行时形态: 4.5MB
  - HUD 显示: 自动驾驶状态 / 障碍物 / 路线 / 距离

七、游戏厂商修复建议
============================================================
1. 服务器端验证: 检测不可能的移动模式（完美路径跟踪）
2. 输入验证: 检测非人类输入特征（恒定精度转向）
3. 内存保护: 对 UE 反射系统关键属性加完整性校验
4. 反外部读取: 检测 NtReadVirtualMemory 大量调用模式
5. 地图数据保护: 对 glTF 网格数据加运行时完整性校验
6. 卡住检测: 正常玩家不会精确执行"卡住→倒车→重规划"循环
7. 补给行为: 检测自动化补给购买模式（精确触发条件）
